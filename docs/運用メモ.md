# サイト運用メモ

Affectosphere Lab サイト（https://lab.affectosphere.group ）を更新するときの場所と手順。

## 置き場所

| 用途 | パス |
|---|---|
| **作業コピー（これが正）** | `~/sites/affectosphere-lab` |
| 公開リポジトリ | GitHub `keito-git/affectosphere-lab` の `main` |
| Git倉庫（履歴のみ・展開なし） | `~/.local/git_store/affectosphere-lab` |
| 旧作業フォルダ（2026-07で停止） | `~/Desktop/研究/affectosphere-lab` |

- 作業コピーは **iCloudの外**（`~/sites`）に置く。iCloud配下だと同期でGit操作が数分〜数十分かかり、過去に `.git` のロックで push 不能になった。
- `/tmp` 配下はmacOSが自動削除する。2026-09の作業コピーはこれで消えた。一時領域で作業しない。
- 旧Desktopフォルダは履歴が古く（39コミット遅れ）、未コミットの変更も残っている。**参照用**として残置。

## 公開の流れ

`main` に push すると Netlify が自動でビルド・公開する。手動のデプロイ操作は不要。
反映は通常1〜3分。

```bash
cd ~/sites/affectosphere-lab
git pull                 # 先に最新を取り込む
# …編集…
npm run build            # astro check + astro build。型エラーがあるとここで止まる
git add -A && git commit -m "…"
git push
```

**`npm run build` を必ず通してから push する。** `npm run build` は `astro check && astro build`
であり、型エラーは `astro build` 単体では出ない。過去に型エラーのまま push して2回デプロイが
失敗している。

表示確認は `npm run preview`、またはビルド済み `dist/` を `python3 -m http.server` で配信する。

## よく触るファイル

| 内容 | ファイル |
|---|---|
| 業績 | `src/data/publications.ts` / `publications.en.ts` |
| News | `src/data/news.ts` / `news.en.ts` |
| 研究領域の本文 | `src/data/research-domains.ts` / `.en.ts` |
| 研究の地図（段・領域・業績の対応） | `src/data/research-map.ts` |
| AI for Science | `src/data/ai-for-science.ts` / `.en.ts` |
| ナビのタブ順 | `src/data/site.ts` |
| ビジョン本文 | `MANIFESTO.md` / `MANIFESTO.en.md` |

- 日本語ページと英語ページは**別ファイル**。片方だけ直すとずれる。
- 業績を1件足したら `research-map.ts` の `publicationStage` と `publicationDomain` にも追加する。
  登録しないと研究の地図に載らない（地図のページに「未配置 n件」と出る）。
- 同じ研究のプレプリントが後で採録された場合は、**新しい項目を足さずに既存の項目を書き換える**。
  同じ仕事が2件に数えられ、地図の件数がずれるため。

## 書き方の約束

- Newsの本文中の人名は「井下」。英語版は "Inoshita"。
- 論文タイトル・受賞名・掲載誌名は**推測しない**。本人からもらった表記をそのまま使う。
  英語タイトルを勝手に訳さない。
- インパクトファクター等の数値は、出どころが確認できるときだけ載せる。

  `public/favicon.svg`）。書き出し済みのファイルは `~/Desktop/Affectosphereロゴ/`。

## 画像

`scripts/optimize-images.mjs` が各画像の `-800.webp` / `-1600.webp` を作り、
`src/data/image-dimensions.json` に寸法を書き出す。元画像は書き換えない。
画像を足したら実行する。
